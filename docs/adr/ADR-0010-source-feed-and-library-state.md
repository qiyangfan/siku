# ADR-0010：来源目录单向喂养与库域状态

- **状态**：已接受
- **日期**：2026-09-23
- **关联**：细化 ADR-0004 的摄取入口与红线 3（语料唯一事实源）；在 ADR-0003 的
  存储三件套内新增库域状态库；承接 ADR-0002 本地优先

## 决策

1. **语料本体只认受管 vault；用户配置的目录是"来源"（feed），不是语料本体**。
   扫描对来源目录只读、单向 copy-in（内容哈希确定性暂存 → 既有幂等摄取管线），
   与手动上传共享同一身份派生（同内容同名 → 同 `source_id` → 幂等收敛）。
2. **时间只驱动扫描，不驱动重算**：serve 内置轮询（stat 快选 + SHA-256 确认，
   不引入文件监听依赖）只做变更检测、入库与对账；重嵌/重提取/重总结全部事件驱动
   （内容或模型配置变化），图谱/wiki 保持显式触发。
3. **删除语义为标记 + 显式清理**：上游内容变更 → 新版本入库、旧版本自动标记
   `superseded` 并退出检索（磁盘保留）；原件缺失只标记 `missing`；物理删除仅能由
   用户显式清理（携带确认标记）触发，任何自动路径不得删除语料。
   手动导入文档可按真实 `source_id` 单项确认移除（reason=`user_removed`，
   2026-10-02 增补）：清理边界 = 受管副本 + 同来源检疫副本 + 无模型索引消减 +
   旧图谱/Wiki 快照失效，外部原件与来源目录永不触碰；同步登记引用的来源不走
   该入口。完整收尾（文件/索引/可读派生物）全部完成才清除标记，部分失败保留
   可按原 ID 重试；全量清理遇 `user_removed` 同样必须走完该收尾管线。
4. **库域状态独立持久化**：来源注册表、变更缓存、tombstone、扫描间隔存
   `data/library.sqlite3`；它是状态而非派生物，任何重建不得清除，与可重建的
   检索索引库物理分离。同库写入（导入/摄取/扫描写入/清理/移除/索引/图谱/wiki/
   来源启停）共享跨进程文件锁（`vault/.siku/library.lock`），锁后重验扫描计划。

## 理由

1. 红线 3 的可重建性（按 `source_hash` 单文件重抽与全量重建）要求原件在 siku
   控制下持久保存；外部目录的文件卫生（清理、移动、网盘占位符、断连卷）不可控，
   把事实源押在上面等于让重建链随缘。单向 copy-in 同时把管线与脏环境隔离：
   摄取永远只面对已落盘的受管副本。
2. 派生物失效只有"上游变了"一个原因。BYOK 计费模式下，定时重嵌/重总结是在用户
   看不见处烧钱（产品伦理），且结果与上次相同（工程浪费）；扫描对账是纯本地哈希
   比对，成本与变更量成正比。
3. 自动化的安全边界与既有"全量重建需确认"同构：自动只做加法与标记，一切破坏性
   动作必须显式确认。
4. tombstone 必须活过重建：放在重建即清的索引库会在首次重嵌时丢失删除记忆；
   独立小库是 SQLite 三件套内的最小合规解。

## 被否选项

- **就地监听任意用户目录（in-place）**：事实源失控，违反红线 3 的重建前提；
  watchdog/inotify/FSEvents 跨平台语义分裂且违反红线 6（核心轻量）；秒级入库对
  个人知识库无价值。
- **双向同步**：删除/改名回写是同步盘产品的复杂度，本产品只需要"进得来"。
- **周期性全量重算**：见理由 2，直接否决。
- **库域状态进 config.toml**：config.toml 是模型供给契约（三节、0600、环境变量
  层），混入库域运行状态污染能力边界；tombstone 天然是数据不是配置。

## 代价与风险

- 喂养是复制：原件在来源处与 vault 各存一份；个人规模可接受，超大原件走既有
  "附件链接模式"触发项（ADR-0004 台账），不由本 ADR 扩权。
- 来源目录整体消失（卸载/断连）可能被误判为批量删除：保守护栏——枚举失败或
  登记非空但本轮枚举为 0 判定为"源不可达"，本轮顺延并记录，不批量标记。
- 改名识别只覆盖"消失 + 同哈希出现"的简单形；改名同时改内容退化为"旧标
  superseded + 新入库"，语义仍安全（tombstone 兜底）。

## 复核信号

- 出现多设备同步 vault 的强需求 → 同步伴侣另行立项重评，不在本 ADR 内扩权。
- 出现秒级写入密集的来源目录导致扫描压力 → 重评事件监听（以不引第三方重依赖
  为先决）。
- purge 误删反馈显著 → 重评 tombstone 保留期策略（如 superseded 自动保留 30 天）。
