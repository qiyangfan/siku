# ADR-0003：存储三件套——SQLite + LanceDB + 内存图/parquet

- **状态**：已接受
- **日期**：2026-09-17

## 决策

| 层 | 选型 | 约束 |
|---|---|---|
| 元数据/全文 | SQLite（WAL + JSON1 + FTS5） | 连接必须开 WAL；中文检索必须分词（插件或预分词），禁裸 FTS5 |
| 向量 | LanceDB embedded | 与 GraphRAG 生态兼容，磁盘列存 |
| 图谱 | 内存图（NetworkX 起步，10⁵ 边级换 igraph）+ parquet 落盘 | 图不引入独立数据库 |
| 正文 | 磁盘 Markdown，Obsidian vault 兼容 | 永不入库，见 ADR-0004 |

## 理由

1. **本地优先 = 零运维、单文件夹数据目录**。任何 server 形态组件都是架构倒挂；
2. **规模论证**：个人知识库 10⁴–10⁵ 节点全量进内存不足百 MB——graphify 对
   energy-ai-platform 实测 7553 节点 / 22937 边 / 319 社区，全量内存操作无压力。
   为这个量级引入图数据库是仪式税；
3. 检索质量层（混合召回 + 重排，ADR-0006）对向量库的要求只是"嵌入式 + 过滤可靠"，
   LanceDB 全覆盖。

## 被否选项

- **Neo4j**：JVM server 进程，违背零运维；等真做成多用户服务端再说；
- **Kuzu**：本是嵌入式图库最佳候选，但项目 2025 年已归档停维护——不在死项目上起步；
- **Qdrant/Milvus server**：同 Neo4j 理由；
- **sqlite-vec**：可行备选（单文件更少），但百万级向量上限 + 过滤功能薄；LanceDB
  同为嵌入式，能力天花板更高；
- **独立 NoSQL（MongoDB/Redis）**：文档型需求已被 SQLite JSON1 + Markdown 文件本身覆盖；
- **正文入库**：用户数据锁定，与 vault 兼容路线冲突。

## 代价与风险

- 三种存储格式并存（SQLite/parquet/LanceDB），数据目录结构需要文档化（`data/` 布局）；
- SQLite 写并发弱——单用户产品定位下可接受，且一切写入经单写者封装。

## 复核信号

语料超过 10⁶ chunk 或出现多用户并发写 → 重开本 ADR（但"单用户本地优先"产品定位本身
不因技术压力改变）。
