# ADR-0009：模型供给全面 BYOK 端点化与通道化基线

- **状态**：已接受
- **日期**：2026-09-18
- **关联**：修订 ADR-0006 的"embedding 用本地模型"决策；延伸 ADR-0005 的可插拔
  Provider 模式；承接 ADR-0002 的"本地可用"产品形态

## 决策

siku 不内置任何模型。LLM、embedding、reranker 三类模型一律经用户配置的端点供给
（云端 API 或自部署的 Ollama/vLLM/LiteLLM），配置按 CLI 参数 > 环境变量 >
`config.toml` 分层解析；凭证走 0600 配置文件明文或环境变量间接引用，且绝不进入
日志与持久化产物。

1. **端点契约只认两类**：openai 兼容 `POST /embeddings` 与 `POST /rerank` 通用形
   （Jina/Cohere/硅基流动/LiteLLM 共同形）；厂商特殊形（如 vLLM score API）经
   LiteLLM 代理统一，不做一对一适配层。
2. **reranker 是可选件**：`reranker=none` 时按 RRF 融合分数排序——Ollama 等主流
   自部署端点没有 rerank API，这是本地人群的必需能力，其精度代价由 golden set
   通道基线显式量化。
3. **进程内本地模型删除**（bge-m3/bge-reranker/sentence-transformers/torch）：
   权重不进安装包，模型参照经协议可达（Ollama、硅基流动均提供 BAAI/bge-m3）。
4. **golden set 基线通道化**：每个模型通道维护自己的基线快照，回归闸门语义不变
   （同通道不低于基线即通过）；上游模型漂移由该通道分数变动捕获，不再依赖某个
   "永久参照模型"。

## 理由

1. **产品形态定调**（2026-09-18）：对标 opencode 供给模式——现阶段全 BYOK，商业化
   后以"托管模型通道"入场；数据不出本机从来不是产品约束，"本地可用"（不依赖服务器
   部署）才是，而端点模式两者皆满足。
2. **隐私面没有扩大**：`/api/ask` 本就将检索片段发往云端 LLM；embedding 端点化只是
   把同一条线贯彻一致。
3. **体积与分发**：进程内 bge（torch + 4.4GB 权重）是 7.3GiB sidecar / 4.1GB DMG 的
   全部来源；删除后安装包降至数百 MB，冷启动从 20s+ 到秒级。
4. **质量裁决更诚实**："通道基线"度量用户实际使用的通道；进程内裁判既不独立
   （bge-m3 也是可替代候选）也不守护真实路径（漂移发生在端点侧）。

## 被否选项

- **保留进程内 bge 作为 golden set 参照裁判**：独立性是假的（现任模型当裁判），
  且对端点侧漂移零保护；被"为现状辩解"评审否决。
- **进程内 bge 作为可选离线打包**：PyInstaller 冻结二进制无法运行时加依赖，等价于
  双 sidecar + 下载管理器，复杂度不成比例；离线需求由 Ollama 端点覆盖。
- **FTS5-only 降级检索**（无 embedding 时退化单路）：改变排序语义且掩盖配置缺失；
  保持明确报错 + 配置指引。
- **多租户云端 SaaS**：账号/存储/隔离成本与个人知识库信任门槛冲突，商业化前不做
  （ADR-0002 触发器保留重评口子）。

## 代价与风险

- 无端点即无向量检索：报错必须可行动（config 模板 + 一分钟 Ollama 路径）。
- 云端 embedding 的中文质量需数据裁决：通道基线给出实测；不满意可换 BAAI/bge-m3
  云端端点，模型参照不因删除进程内形态而消失。
- `reranker=none` 降精度：显式配置 + 基线数据呈现，不静默。
- CLI 默认通道消失是破坏性变更：产品未发布，现在是一次性切换的最低成本时机。

## 复核信号

- 出现"用户不愿装 Ollama 也不配云端 key"的显著比例 → 重新评估内置轻量量化模型
  （onnxruntime 系，非 torch）。
- LiteLLM/端点生态出现 rerank 事实标准收敛 → 简化 `/rerank` 契约说明。
- 商业化启动 → 托管模型通道立项（本 ADR 的 provider 模式直接承载，无需新架构）。
