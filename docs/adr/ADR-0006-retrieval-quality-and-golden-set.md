# ADR-0006：检索质量层与 golden set 回归门禁

- **状态**：已接受（2026-09-18 部分修订：模型供给改为 BYOK 端点、进程内本地模型删除、基线通道化，见 ADR-0009；golden set 闸门与混合召回 + 重排架构不变）
- **日期**：2026-09-17

## 决策

检索链路固定为四段：

```
bge-m3 向量化 → BM25 混合召回 → bge-reranker 重排 → 返回
                                    ↑
            golden set 回归（几十个"问题 + 应命中文档"标注对）是合入门禁
```

- embedding 用本地模型（bge-m3，多语言，中文语料必需）；图谱抽取用 API 强模型
  （BYO key，graphify + DeepSeek 已验证可行且个人预算可承受）；问答 LLM 可配置，
  本地/API 双通道。
- **golden set 是检索行为的可执行规格**：改切块、换 embedding、调召回/重排参数，
  必须跑回归；未跑不得合入。golden 文件入库，变更必须连同理由提交。

## 理由

1. 2026 年共识：纯向量 RAG 在多跳关系问题上不够用（GraphRAG 已被 Gartner 列为独立
   趋势）；BM25 混合召回补关键词与精确匹配，重排补精度——三层各管一段；
2. 中文语料是主场景，bge 系是中文检索的实证强基线；
3. 无回归集的检索调优是玄学：检索参数牵一发动全身，没有客观分数就无法区分"变好"与
   "变了个口味"。golden set 把品味问题变成回归问题。

## 被否选项

- **单路向量裸奔**：省事，但精确匹配（型号、错误码、人名）场景召回质量塌方；
- **上来就上 GraphRAG 全家桶做检索**：图谱检索成本高，先混合向量打底，图谱检索按需
  叠加（图谱的主用途是 wiki 生成与关系浏览，不是第一检索通道）；
- **golden set 上百条起步**：标注维护成本先于产品价值爆炸——几十条覆盖核心场景即可，
  随真实查询沉淀增长。

## 代价与风险

- golden set 的标注本身有偏（出题人偏差）；缓解：标注对从真实使用中的失败案例沉淀，
  而非闭门造车；
- 重排引入一次额外推理延迟；本地模型可接受，API 模型需缓存策略。

## 复核信号

回归通过率连续不降但用户满意度降 → golden set 覆盖面缺陷，扩标注而不是调参；
中文分词质量成为瓶颈 → 重开 FTS5 分词器选型（ADR-0003 的分词红线细则）。
