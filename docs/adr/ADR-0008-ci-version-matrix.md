# ADR-0008：CI 版本矩阵——两端覆盖与哨兵降级触发器

- **状态**：已接受
- **日期**：2026-09-17

## 背景

`requires-python = ">=3.12"` 声明了开放下限；owner 质疑是否需要为声明区间逐版本真实
跑测试（"一个要求 12，一个要求 13，完全可以用 14 一把跑"）。争议：多版本矩阵是否仪式税。

## 决策

1. **push 触发的 CI 跑两端**：`3.12`（`.python-version` 钉定的开发基准）+ `3.14`
   （当前最新稳定版）。中间版本（3.13）不跑——兼容性破坏集中在两端（上限的 stdlib
   移除、下限的特性差异），中间版本诊断价值最低。
2. **action 运行时钉 node24**：`actions/checkout@v7`、`astral-sh/setup-uv@v10.1.0`
   （该仓库不维护滚动大版本标签，必须钉精确版，升级交给 Dependabot）、
   `actions/setup-node@v7`；ui 作业经 setup-node 安装 Node 24 工具链。
3. **哨兵降级触发器**：CI 总时长超过 2 分钟时，将 3.14 作业从 push 触发降级为
   `on: schedule` 每周定时跑，push 只保 3.12 基准。验证不删，成本换个频率付。

## 理由

**兼容性是单向阀**：新解释器大体能跑旧代码，旧解释器一定跑不了新代码。因此两端作业
守护的是不同失败模式，互不可替代：

- 3.12 基准守护**"我们自己写的代码"**——防止无意间使用 3.13+ API（`typing.TypeIs`、
  `Path.full_match` 等）；ruff `target-version` 只能拦部分语法，运行时新 API 误用
  只能靠低版本真跑暴露。本仓库代码大量由 AI/agent 生成，抄最新 API 的风险天然偏高。
- 3.14 哨兵守护**"生态的变动"**——stdlib 做减法（3.13 已移除 cgi/crypt 等）、依赖
  闭包随解释器漂移。且阶段一经 `uv tool install` 分发，用户侧解释器异构，3.14 用户
  是真实存在的安装路径。

成本事实：两端并行执行，墙钟不叠加，整套 CI 当前 17 秒。

## 被否选项

- **只跑 3.14 一把**：宣称覆盖下限，实际留出"下限泄漏"盲区（新 API 误用）；
- **只跑 3.12**：留出"上限断裂"盲区（stdlib 移除、依赖漂移），3.14 用户首次安装
  即成为发现者；
- **收窄 `requires-python` 到 `<3.13`**：声明与验证一致，但强迫新机器用户下载 3.12、
  每年手工抬上限，把生态兼容性的发现权交给用户报障；
- **加跑 3.13**：两端已覆盖其可能暴露的问题类别，纯增成本。

## 实现踩坑（已修复，记录防复发）

- `hashFiles()` 只能用于 step 级 `if`，写进 job 级 `if` 会导致整个 workflow 文件
  校验失败（0 秒 startup failure）；
- setup-uv 无滚动大版本标签，`@v10` 解析不到，须钉 `@v10.1.0`。

## 复核信号

阶段二 Tauri 打包把解释器钉死进产品后，"用户侧解释器异构"前提消失 → 重新评估哨兵
作业的必要性（届时 3.14 可能只剩本地开发前瞻价值）；CI 触达 2 分钟阈值 → 执行降级。
