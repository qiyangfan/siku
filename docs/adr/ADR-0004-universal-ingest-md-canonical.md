# ADR-0004：万能摄取——一切格式归 Markdown 事实层

- **状态**：已接受
- **日期**：2026-09-17

## 背景

初始定稿只有 Markdown；用户随后要求 PDF/Word/PPT/Excel 全兼容。争议：多格式进存储层，还是进摄取层。

## 决策

**摄取格式全部放开，存储定稿不变：万能摄取 → Markdown 事实层 → 原件留存溯源。**

```
vault/
  attachments/   ← 原件拷贝（本地优先要求单文件夹可备份可迁移，默认拷贝不外链）
  notes/         ← Markdown 投影（frontmatter 记 source_hash / 页码锚点）
```

| 格式 | 方案 | 协议 | 要点 |
|---|---|---|---|
| PDF | pypdf（默认，ADR-0013）/ Docling + MinerU（可选重型） | BSD / MIT / AGPL-3.0 | 默认轻量文本抽取；扫描件给 OCR 转换指引，不内置模型 |
| Word | pandoc（外部二进制，桌面随包固定版本） | GPL-2+（外部进程无传染） | 标题/表格/脚注/图片全收；旧 .doc 给现代格式转换指引 |
| PPT | python-pptx | MIT | 按 slide 切块 |
| Excel | openpyxl | MIT | sheet → Markdown 表格块；超长表截断取样+行数注记 |
| EPUB/HTML | 内置解析器 | — | 零边际成本 |

> 修订（2026-10-02，ADR-0013）：默认 PDF 方案由 Docling 改为 pypdf 公开文本提取
> ——默认安装与桌面包不携带 torch 系重依赖，扫描件与旧二进制 Office 以稳定
> 错误码给出可行动转换指引；Docling 保留为可选 extras 供复杂版面需求评估。

三条工程红线：

1. **切块必须结构感知**（章节/slide/sheet），禁止 token 窗口硬切——切块边界来自文档
   结构，否则图谱抽取质量先崩；
2. **溯源锚点在抽取时写入** frontmatter 与块属性（`source_hash` + 页码/slide 号/sheet 名），
   否则引用只能到文件名，体验差一档；
3. **幂等重抽**：`source_hash`（原件 SHA-256）变更只重抽该文件；换引擎/换模型全量重建，
   语料永远可再生。

## 理由

检索、切块、图谱抽取、wiki 生成整条下游管线只应面对一种规范格式——N 种格式进下游 =
每个环节 N 份 bug。Markdown 投影可编辑可 diff，白吃 Obsidian 生态兼容。原件留存是
溯源的锚：聊天引用跳回"PDF 第几页"靠原文 + 抽取锚点，不靠解析残骸。

## 被否选项

- **多格式进存储层**：下游管线按格式分叉，维护成本乘以格式数；
- **Office 在线预览/编辑**：这是知识库不是文档编辑器，保真度战争不参战——"打开原文"
  交给系统默认应用；
- **原件外链不拷贝**：破坏单文件夹可迁移性；大文件（>百 MB 级视频等）未来用"链接模式"
  例外处理，默认仍是拷贝。

## 复核信号

某格式抽取质量差评持续（如扫描件占比高的语料）→ 在 Extractor 接口内换/加引擎
（ADR-0005），不改存储契约；Excel 出现深度查询需求 → 加 DuckDB 直查通道，不塞进检索层。
