# 提案：桌面资料管理（导入/摄取/索引界面与进度反馈）

## Why

桌面用户现在唯一能让语料进 vault 的途径是命令行：把文件手工拷进平台数据目录下的
`vault/`，再执行 `siku ingest`/`siku index`。这使桌面应用停留在「演示可用」——
docs/desktop.md 有遗留注记，HANDOFF（2026-09-19）将其列为下一阶段候选第 2 项。
设置中心解决「配模型」，本 change 解决「进资料」，两者合成完整的无 CLI 上手体验。

## What Changes

- 新增资料库 API（additive，OpenAPI 快照显式刷新）：
  - `GET /api/library`：返回桌面 vault 的来源级清单——来源名、相对路径、
    `source_hash`、摄取状态（已摄取/待重抽/已忽略）与索引状态，全部派生自既有摄取
    元数据，不复制第二份事实。
  - `POST /api/library/ingest`：触发增量摄取后台任务（复用既有 `siku ingest` 幂等
    管线）；`GET /api/library/jobs/{id}` 以 HTTP 轮询返回进度（完成/失败计数与当前
    文件）。不建立 WebSocket/SSE 长连接——单用户 loopback 场景轮询最简且够用。
  - 摄取任务完成后自动衔接增量索引；提供显式全量重建入口（需确认标记），承接设置
    中心 embedding 变更告警的重建出口。
- UI 新增资料库视图：来源清单（状态徽标）、导入入口、摄取进度反馈、全量重建入口
  （二次确认）与空状态引导。
- 导入语义：导入 = 把用户选定文件复制进 vault 既有布局（attachments/ 原件）后走
  既有摄取管线；不移动、不改写用户原文件。
- 摄取后台化仅限 serve 进程内：任务状态只存内存，不引入任务队列或新存储；崩溃恢复
  = 按幂等语义重跑。

## 受影响决策

- 红线 2 / ADR-0002：UI 只经 localhost HTTP API——导入、进度、重建全部经新增端点。
- 红线 3 / ADR-0004：摄取幂等与 `source_hash` 语义不变；导入只新增语料字节，派生物
  全部经既有管线再生，UI 无任何写回投影的路径。
- ADR-0001：文件选择等原生能力只产出「路径」交内核读取，文件内容一律由内核读取；
  Tauri invoke/事件不承载语料字节。

## 与项目路线的关系

HANDOFF 下一阶段候选第 2 项（2026-09-19 对齐排序 1→2→3）。与设置中心无硬依赖
（摄取/索引不依赖 LLM 配置），顺序服务于上手链路：先能配模型、再能进资料。

## Non-goals

- 不做图谱/wiki 的生成与重建入口（继续走 CLI；阅读视图见
  `add-browse-graph-wiki-views`）。
- 不做文件/笔记编辑器：视图只读展示来源状态，不编辑 Markdown 投影。
- 不做删除语料的 UI：删除 = 文件系统删除 + 重抽，先保持 CLI 路径，避免误删面。
- 不做目录监视自动摄取（watcher 自动化另行评估；首版为手动导入 + 手动触发）。
- 不做文档内容预览渲染（内容查看属浏览视图范围，本 change 只做状态与元数据）。
- 不改变既有 `/api/ingest`、`/api/search` 等端点契约；OpenAPI 变更仅限新增端点。
- 不做多任务并行摄取、任务持久化与历史记录（单任务 + 内存状态 + 幂等重跑已够）。

## 边界裁决

- vault 布局不变：导入目标按既有约定（notes/ 投影 + attachments/ 原件），不引入新
  存储位置；导入只复制字节，原文件留在用户处不动。
- 一次只允许一个摄取任务（串行逐文件），与 CLI 行为一致，避免 SQLite 写竞争；重复
  触发返回 409。
- 文件类型白名单复用既有摄取支持（PDF/Word/PPT/Excel/EPUB/HTML/Markdown），其余按
  既有「忽略」语义在结果中报告。
- 摄取失败的持久化表现（last error 落元数据 vs 仅在任务结果中呈现）在约束冻结裁决；
  在此之前不在 spec 中臆造失败状态语义。
