# 提案：完成本地问答内核与最小对话 UI 纵切面

## Why

siku 的产品核心不是“把已有服务画出来”，而是让用户把自然语言问题交给自己的知识库，
得到带来源依据的答案。当前 Phase 1-3 已完成摄取、混合检索、图谱和 wiki，但仓库中没有
问答编排、答案引用协议或 `/api/ask`，因此还没有形成产品主价值闭环。

上一阶段冻结了检索 API，但只返回检索片段；本 change 在不改变检索算法的前提下，把检索
结果受控地交给用户自配的 LLM，生成可核验的答案，并由 localhost HTTP API 和最小对话
界面暴露。首版采用无状态、非流式问答，先把“问题 → 有证据的回答”做成可测试的稳定能力。

## What Changes

- 新增问答领域服务：复用既有 `SearchService`，构造有界上下文，调用可注入的 LLM provider，
  解析结构化回答，校验引用只指向本次检索上下文；正常回答必须至少带一条引用，并在证据
  不足时明确拒答。
- 新增 `POST /api/ask`：返回答案、引用、检索摘要、模型身份和 `request_id`；错误复用
  现有稳定 HTTP 状态/错误码体系，问答专用文案不得改变既有 graph/wiki 端点的错误语义。
- 扩展 `siku serve` 的 LLM 配置面，使 API 服务支持 `base_url`、模型名和 key 环境变量，
  默认行为继续使用 DeepSeek + BYO key。
- 初始化并实现最小 React 对话界面：问题输入、回答展示、引用展开、加载/错误/无证据状态；
  UI 只经 localhost HTTP API，不包含检索或提示词业务逻辑。
- 增加 fake LLM/provider 输出故障矩阵与问答契约测试；不调用真实 LLM，不改变已有 golden set
  的检索基线。问答输出校验失败沿用外部依赖不可用的 503 语义，但不得复用图谱抽取的
  `graph_extraction_error`（后者是 422），也不得向用户声称问答结果已缓存或可续传。

## 受影响决策

- ADR-0001：落实 Python 问答编排、TypeScript 对话界面和 localhost 服务边界。
- ADR-0002：坚持本地优先、BYO key、无账号/无云端持久化，LLM 仅瞬时接收检索上下文。
- ADR-0005：问答依赖项目自有 provider 协议，不绑定第三方 SDK 或服务存储格式。
- ADR-0006：复用既有混合检索与 golden set；问答层不得绕过检索直接把全量语料交给 LLM。

## 与项目路线的关系

这是 Phase 4 的核心纵切面，优先于浏览、图谱画布和 wiki 阅读 UI。完成后，用户可以启动
本地内核、输入问题、得到带来源引用的答案；后续再补资料浏览和派生知识视图。Phase 5
Tauri 打包和 Phase 6 签名更新不提前启动。

## Non-goals

- 不实现流式回答、会话记忆、多轮上下文、对话标题、历史持久化或多用户会话。
- 不实现账号、登录、token、付费订阅、支付、配额、多租户、远程鉴权或 SaaS 后端。
- 不做云端存储、遥测、用户文档上传服务器或跨设备同步。
- 不改 BM25/向量/RRF/reranker 算法、embedding 模型、golden set 口径或已有检索排序。
- 不实现图谱检索、图遍历问答或把图谱摘要冒充问答证据。
- 不实现资料目录、图谱画布和 wiki 阅读 UI；这些是问答闭环后的支撑视图。
- 不做 Tauri 壳、签名、公证、自动更新、GitHub Releases 或 Homebrew 打包。

## 边界裁决

“对话”在本 change 中指无状态的单轮 grounded QA，不等同于完整聊天产品。回答必须只基于
本次检索上下文；没有足够证据时返回可解释的“证据不足”，不得让模型自由发挥。后续如果
需要多轮会话或流式传输，必须先单独冻结会话状态和传输协议。
