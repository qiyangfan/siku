# 提案：来源目录同步（受管喂养 + 定时扫描 + 标记式删除）

## Why

进资料目前只有手动导入与 CLI 两条路，而"丢进目录自动进知识库"是 Phase 1 一句话
目标里承诺的产品意象，尚未兑现。桌面用户重复导入同一批目录文档的摩擦最大；BYOK
计费背景下，用户还需要"内容没变就绝不动、绝不重复扣费"的确定性。owner 2026-09-23
点名立项并裁决方向：受管语料根 + 外部来源单向喂养、扫描轮询（不监听）、重算事件
驱动、标记式删除 + 显式清理——完整裁决与被否选项见 ADR-0010。

## What Changes

- 新增 `siku.sync` 内核模块：
  - 库域状态库 `data/library.sqlite3`（非派生物，任何重建不清除）：来源注册表、
    变更检测缓存、tombstone、扫描间隔。
  - 扫描器：`(大小, mtime)` 快选 + SHA-256 确认 → 命中变更的文件走确定性暂存
    copy-in，复用既有幂等摄取管线；改名识别；源不可达保守顺延。
- serve 内置轮询调度：间隔存注册表（默认 300 秒，0 = 关闭），改间隔免重启生效；
  与既有单任务槽互斥复用——自动扫描检测阶段不占槽，槽忙时顺延不报错。
- 资料 API 增量（additive，OpenAPI 快照显式刷新）：
  - `GET/POST/PUT/DELETE /api/library/sources`：来源目录列举、注册、启停、移除
    （移除只删登记，不动已入库文档）。
  - `POST /api/library/scan`：立即扫描（复用任务进度机制，可选全量哈希校验）。
  - `POST /api/library/purge`：确认式物理清理全部已标记（superseded/missing）文档。
- `GET /api/library` 清单扩展：摄取状态新增 `missing`（原件缺失）与 `superseded`
  （被新版本替代、已退出检索）；喂养条目附来源目录中的上游路径。
- CLI：`siku scan` 一次性扫描（中文报告；供脚本与偏好 OS 定时器的高级用户）。
- UI 资料库视图扩展：来源目录管理区、立即扫描入口与进度、缺失/已替代徽标、
  清理入口（二次确认）。

## 受影响决策

- 红线 2 / ADR-0002：扫描调度、来源管理、清理全部位于 serve 内核，经 localhost
  HTTP API 暴露；UI 零业务逻辑。
- 红线 3 / ADR-0004：语料唯一事实源不变——喂养只向 vault 增加字节（copy-in），
  对来源目录只读不写回；`source_hash` 幂等与单文件重抽语义原样复用；自动路径
  永不物理删除，删除 = 标记（tombstone）+ 显式确认清理。
- ADR-0003：`data/library.sqlite3` 属 SQLite 三件套内的自持 schema；它是状态不是
  派生物，与可重建的 `retrieval.sqlite3` 物理分离。
- ADR-0010（新增，随本 change 提交）：上述裁决、理由与被否选项的完整记录。

## 与项目路线的关系

Phase 5++「进资料」链路的自动化延伸，owner 2026-09-23 对齐排序点名立项。与
Backlog 中"vault 同步伴侣"无关（那是只读发布/外发方向）；本 change 是入站摄取
自动化。归档时回写 ROADMAP 勾稽。

## Non-goals

- 不做双向同步/写回来源目录：来源目录永远只读。
- 不做文件系统监听（inotify/FSEvents/watchdog）：轮询是唯一扫描机制。
- 不做任何周期性重算：定时扫描不得触发全量重嵌、全量重抽、图谱重建或 wiki 生成；
  重算只由内容变更（增量）、用户显式触发或模型配置变更（既有告警出口）驱动。
- 不做自动物理删除：清理必须显式携带确认标记；不做回收站 UI（tombstone 即缓冲层）。
- 不做网络卷/远端目录特殊适配：按普通本地目录对待，不可达时顺延并记录。
- 不做多任务并行：扫描、清理与摄取/重建共用既有单任务槽。
- 不改既有 `/api/library/ingest`、`/api/library/rebuild`、任务进度与摄取管线契约；
  OpenAPI 变更仅限新增端点与清单字段扩展。
- 不扩展 config.toml：扫描间隔等库域状态一律走注册表与 API（config.toml 是模型
  供给契约）。

## 边界裁决

- 扫描检测阶段（stat 快选 + 哈希 + 注册表 diff）只读、不占任务槽；仅当存在待入库
  变更时才取槽执行 copy-in + 摄取 + 增量索引。手动扫描无变更时也返回任务快照
  （瞬时 succeeded，items 为空）。
- 身份与去重语义与手动导入完全一致：同内容同名幂等跳过；同内容不同文件名是两份
  独立文档（身份按内容 + 文件名派生，本 change 不新造去重规则）；上游改名（消失
  路径的内容哈希在新路径出现）识别为移动，仅更新登记。
- `superseded` 文档在索引同步时剔除 chunk；`missing` 文档保持现状仅标记；purge
  才物理删除（attachments 原件 + notes 投影 + 索引即时消减），图谱/wiki 经既有
  重建流程再生。
- 文件白名单复用摄取注册表；白名单外文件按既有"忽略"语义在扫描结果中报告，不
  登记、不入库。
- 源不可达保守护栏：枚举失败，或登记非空但本轮可枚举文件数为 0 → 判定源不可达，
  本轮顺延该源并记录，不做任何标记（防卸载/断连被误判为批量删除）。
