# 提案：内容变更后图谱增量自动维护

## Why

内容变更后，检索索引会自动增量同步（摄取/扫描任务收尾衔接），图谱却是唯一需要
用户手动「更新图谱」的派生物——与「丢进全部文档，自动织成知识图谱」的产品承诺
相悖，用户侧的表现是：新文档摄入了、能检索了，图谱里却看不到它。

技术上不做自动不是成本理由：抽取缓存按 chunk 粒度命中，自动增量刷新的 LLM 开销
仅限新文档的新 chunk，旧 chunk 零调用。真正的缺口是三件基础设施缺失：授权模型
（花用户的 key 需要一次显式同意）、增量资格闸门（换模型/prompt 后缓存键全部失效，
无闸门的自动刷新会静默全量重抽整个语料）、以及失败隔离（抽取失败不应把已成功的
摄取任务判为失败）。

## What Changes

- 新增库级开关 `graph_auto_refresh`（默认关闭），存库域注册表，与自动扫描间隔同
  端点读写、免重启生效；库级而非机器级（config.toml 是模型通道的机器级配置）。
- 资料库任务收尾链（摄取/扫描；CLI `siku scan` 同口径）在索引同步之后，按开关
  自动增量刷新**已存在**的图谱：调用与显式更新同一构建入口（非 rebuild），产物
  与显式更新一致；仅新 chunk 发生 LLM 调用。
- 新增抽取身份闸门：记录上次成功构建的抽取器身份（标识/模型/prompt 版本），与
  当前 LLM 通道不一致时跳过自动刷新并指引显式更新——复刻索引侧「增量拒绝 + 全量
  重建指引」的既有模式，不新造机制。
- 资料库任务终态响应新增可选中文通知字段，报告刷新计数、跳过原因或失败事实；
  刷新失败不改变摄取/扫描的成功终态，旧图谱快照保持可读（原子写保证）。
- 明确边界：不自动创建图谱、不自动重建移除后失效的快照、不自动生成 wiki；不在
  MCP `ingest` 与 CLI `siku ingest` 生效（两者今天连索引都不维护，修复该既有缺口
  另案；单独刷图谱会让图谱比索引还新，破坏派生层次序）。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `graph-wiki`：新增「内容变更后图谱可增量自动维护」需求（开关、前提、跳过语义、
  失败隔离、与显式产物一致）。
- `library-sync`：修订「派生物重算只由事件触发」——内容变更收尾的图谱增量自动维护
  仅在开关开启且前提满足时发生，wiki 仍只显式触发，移除/清理不触发图谱维护。
- `http-api`：扫描设置端点扩展开关读写；新增「资料库任务通知派生维护结果」需求。
- `web-ui`：资料库视图在自动扫描间隔旁提供图谱自动刷新开关与其中文说明。

## Impact

涉及库域注册表（新设置项）、图谱缓存身份记录、资料库任务收尾链与通知字段、
HTTP 契约（`contracts/openapi.json` 快照需刷新）、资料库视图组件与对应测试。
复用既有构建入口、抽取缓存、任务进度与错误映射；不新建调度器、后台守护、成本
预估或第二份设置存储。遵守 ADR-0002（UI↔内核边界）、ADR-0003（存储三件套不变）、
ADR-0004（语料唯一事实源，派生物同入口可重建）、ADR-0009（BYOK：开关即显式授权）、
ADR-0010（库域状态承载自动化偏好）；不新增 ADR——授权模型与边界论证见 design.md。

## Non-goals（不做清单）

- 不自动创建图谱、不自动重建被移除/清理失效的快照、不自动生成或刷新 wiki。
- 不在 MCP `ingest` 与 CLI `siku ingest` 生效；不顺手修复二者缺失的索引自动维护
  （既有缺口，另案评估）。
- 不做图谱增量删边/社区局部重算算法：自动路径与显式更新同入口，仍是全量合并 +
  社区重发现的本地计算（延续 remove-manual-library-document 的既有边界）。
- 不改抽取 prompt、实体归一化规则、社区发现参数与 parquet 三件表结构。
- 不做按次成本预估、配额或预算上限；通知只报告实际发生的抽取与缓存命中计数。
- 不改 config.toml 模型通道结构，不为开关新增机器级配置文件。
- 不新增后台常驻守护或独立调度器；自动维护只挂在既有任务收尾链上。
