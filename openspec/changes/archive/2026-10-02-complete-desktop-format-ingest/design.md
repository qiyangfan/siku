# 设计：轻量默认抽取与随包转换工具

## 当前证据

- `pyproject.toml` 默认依赖未包含 PDF/PPTX/XLSX 解析库；`ingest-pdf` 使用 Docling，Office 库在 extras。
- DOCX 适配器需要外部 pandoc；注册旧 `.doc` 并不代表转换器支持该二进制格式。
- 当前关闭 OCR 仍不能消除 PDF 引擎的布局模型与 torch 依赖。仅安装全部 extras 会使 ADR-0009 的瘦身结果倒退。
- 页面可以接受文件，不等于冻结后的 sidecar 具有该格式抽取能力；须在不含开发工具的包内验证。

## D1：成熟工具完成格式处理

唯一默认方案：文本 PDF 用 `pypdf`，DOCX 继续用 `pandoc`，PPTX 用已有 `python-pptx`，XLSX/XLSM 用已有 `openpyxl`。轻量 Python 解析库进入默认 dependencies，重型 PDF 引擎保持 extras，桌面构建不安装这些重型 extras。

解析器继续通过项目 Extractor/格式适配边界接入，下游只消费自持 Markdown 投影与元数据。pypdf 使用公开文本提取接口，不复制 PDF 解析/布局算法。PDF 每页使用原页序号；空白页可没有正文，但后续页面锚点不得重编号。整份没有可抽取文本的 PDF 失败并说明需要先 OCR 或转换成含文字的 PDF。

DOCX 不改成自写文档遍历器。沿用 pandoc 转换，保留标题、表格与现有图片/脚注处理；PPTX 和表格沿用既有结构锚点及截断注记。XLSM 保持可读表格支持，不执行宏。EPUB/HTML/Markdown 继续沿用已实现适配器，不为统一工具名而重写。

## D2：转换工具随包定位

构建脚本取得上游正式发布的 pandoc 二进制，固定版本、目标平台与 SHA-256，保留许可证及版权说明，并随冻结 sidecar 收集到已知资源目录。构建时完成下载校验，运行时不得联网安装、下载或自行升级。

冻结运行时只使用随包资源的绝对路径；开发/CLI 安装允许沿用系统 pandoc，但缺少时给出安装提示。工具选择与资源定位放在内核，不让 React/Tauri 传入任意可执行文件路径。子进程参数使用参数数组、有限超时和受管临时目录，不使用 shell 拼接。

macOS、Windows、Linux 构建分别验证二进制架构、可执行权限与冻结资源路径。此处验证构建产物，不等于启用发布或宣称所有平台实机安装已验证。

## D3：准确的支持范围与报错

默认范围为含可抽取文本的 PDF、DOCX、PPTX、XLSX、XLSM，以及已有 EPUB、HTML、Markdown。统一注册、API 校验、文件选择提示与 CLI 文档；`.doc/.ppt/.xls` 不再被宣称为可直接抽取，提示转换到对应现代格式。

不含文本、加密无法打开、损坏文件、格式不支持与打包依赖缺失分别沿既有错误映射返回可行动的失败；仅在现有码无法准确表达时新增稳定错误码并同步契约。异常 message 用英文，UI 展示中文建议，不回显凭证或本机完整配置。失败文件不能伪造成功投影或摄取状态。

纯抽取及生成投影不需要模型端点；后续向量索引、图谱和 Wiki 按既有 BYOK 规则执行。不可把“格式解析离线可用”扩展成“未配置端点时完整问答可用”。

## D4：原件与质量边界

原件仍复制到 attachments，投影仍写入 notes；保留同一 `source_hash` 的幂等语义。不做复杂版面完美还原承诺，不新增引擎选择 UI、插件管理器或模型下载器。可选重型适配器不进入本提案的默认桌面交付。

用公开、小型夹具覆盖中英文文本 PDF、跨页空白、表格/标题 DOCX、PPTX 幻灯片、XLSX 多 sheet、XLSM 和失败文件。默认 PDF 引擎变化影响事实层，需检查投影可读性与引用锚点，并执行既有检索 golden set；不通过调整检索基线掩盖抽取退化。

## 验证与回滚

先写适配器与冻结包回归，再实施依赖和资源收集。至少在可用 macOS 环境将系统 pandoc 从 PATH 隔离、清空模型缓存并禁网，执行冻结 sidecar 的 HTTP/CLI 多格式抽取。索引验证使用受控端点 fixture，单独说明其 BYOK 前提。

构建 CI 检查三个平台资源与依赖清单，不含 torch、模型权重或运行时下载；既有签名/安装豁免保持。回滚只替换默认适配及构建资源，不删除用户原件，也不自动改写已有事实层。

当前摄取会按 source_hash 跳过未变化的文件，没有针对换引擎的强制重抽入口；索引 `--rebuild` 只重建派生索引。本件保留已有投影，新的摄取使用新默认引擎，不追加强制重抽功能。需要为既有手动 PDF 重新生成投影时，操作说明须指向本轮另行提案的“确认移除受管副本后从保留的外部原件重新导入”，该能力未实现前不宣称存在一键重抽；来源同步文档继续保留其已有投影。

## 上游依据

- [pypdf 文本提取文档](https://pypdf.readthedocs.io/en/latest/user/extract-text.html)：公开文本提取能力及不提供 OCR 的边界。
- [Pandoc 安装文档](https://pandoc.org/installing.html)：官方各平台二进制分发。
- [Pandoc 手册](https://pandoc.org/MANUAL.html)：DOCX 等输入格式的正式范围；旧二进制 DOC 不在默认支持承诺内。

这些依据决定默认能力边界，库版本与资源校验值须在实施时实际锁定并验证，不能凭提案视为包内已可用。
