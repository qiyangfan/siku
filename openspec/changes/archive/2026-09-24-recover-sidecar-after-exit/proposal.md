# 提案：sidecar 运行中断后可由桌面壳重启

## Why

桌面壳负责启动 `siku-sidecar serve --with-ui`。当前壳只在启动阶段管理 sidecar；启动成功后，网页中的“重试连接”只重新请求 `/api/health`，不能重新启动已退出的进程。sidecar 运行中意外退出时，用户会留在无法工作的页面，且按钮文案暗示了它并不具备的恢复能力。

## What Changes

- 桌面壳在健康就绪后继续监测自己启动的 sidecar 进程与健康接口。
- sidecar 退出或持续无响应时，壳将窗口切回本地恢复页，提供明确的“重新启动本地服务”操作。
- 点击恢复操作后，壳回收旧进程、重新启动 sidecar，并在健康检查通过后返回应用。
- 普通浏览器/Vite 模式保留手动启动命令，并把网页内按钮称为“检查连接”；网页不获得进程控制 IPC。
- React 主框架在所有视图持续显示清楚标为“本地服务”的连接状态；浏览器离线说明在各视图均可见。
- 状态文案统一使用用户可理解的“本地服务”，避免把进程实现细节暴露为“内核”。

## 受影响决策

- **ADR-0001**：Rust 壳继续只负责窗口与 sidecar 生命周期；业务数据和功能仍由 localhost HTTP API 提供。

## 与项目路线的关系

该 change 补齐 Phase 5 桌面壳的运行期故障恢复，不改变 `siku serve --with-ui` 的 CLI 契约或业务 API。

## 不做清单（Non-goals）

- 不在 React 业务页中加入 Tauri IPC 或本地进程控制。
- 不在浏览器/Vite 模式下尝试从网页创建、杀死或重启系统进程。
- 不自动重启 sidecar；进程退出后由用户从恢复页明确触发。
- 不修改 Python 服务、HTTP API、数据存储或 CLI 命令参数。
- 不新增 ADR；此行为沿用 ADR-0001 已确定的壳进程管理边界。

## 规格处理

新增 `desktop-shell` 的运行期 sidecar 故障恢复要求与场景，并增补 `web-ui` 的全局服务状态要求；归档时将 delta 同步到主规格。
