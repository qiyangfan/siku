# 实现评审记录

**状态：实现与验收完成，最终独立代码审查通过。**

## 实现结果

- 问答页使用 `GET /api/notes`、最多两次笔记详情读取及 wiki 社区详情构造最多三条问题建议；不调用模型、不改 API、不直接读本地文件。
- 建议来自真实笔记标题/章节及 wiki 成员实体。已导入的 `SKILL.md` 按普通笔记处理；未导入的 skill 文件不扫描。
- 推荐按钮由 Mantine Button 呈现。长问题的可见标签会缩短，可访问名称、悬停提示及点击后预填的内容均保留完整问题；用户仍需主动发送。
- 没有内容时提示导入资料或生成 wiki；来源读取失败时保留手动提问，某个来源成功时不会被另一个来源的失败覆盖。
- 当笔记为空且 wiki API 返回 `wiki_missing` 时，按空语料展示导入提示，不显示“项目边界”等固定问题。
- 预览页补齐资料库 mock 路由，修复了从更多菜单打开资料库时无法加载的问题。

## 验证

- `npm run lint`：通过。
- `npm run build`：通过；JS chunk 779.64 kB（gzip 232.63 kB），超过 Vite 建议阈值但不阻断构建。
- `openspec validate --changes --strict`：3 个 change 通过；`openspec validate --specs --strict`：8 份规格通过。
- 375px 与 320px 移动预览使用包含长标题和章节的样例语料：页面 `scrollWidth` 与视口宽度相同；建议按钮分别宽 309px 与 254px，最长一条可换行；底栏固定高 65px，仅显示问答、浏览、图谱。
- 长问题展示精简标签，按钮操作填入完整问题，不会自动发起问答请求。

## UI 质量闸门

- 输入与提交仍是主操作，建议作为可跳过的辅助入口；空笔记且 wiki 未生成时不显示固定示例。
- 长内容在移动布局中可换行，触控目标超过 44px 高；完整问题可通过键盘辅助技术读取。
- 推荐只依赖当前已导入语料，不为自动推荐增加模型调用或后台数据访问。

## 独立代码审查

- 审查发现 `wiki_missing` 是空 wiki 的正常状态，最初被当作来源读取失败；已在无笔记场景下与空 wiki 合并处理并补充回归测试。
- 最终独立复审确认推荐只读取现有 API 数据，不调用模型或自动提交，未发现遗留代码问题。
