# 设计：从笔记和 wiki 构造提问建议

## 信息架构与视觉

场景是本地知识库工具。用户进入问答页 3 秒内仍应先看到问题输入框和提交入口；内容建议位于输入框与提交操作之间，作为可跳过的次级帮助。

继续使用 `ui/design-system/MASTER.md` 中的 Mantine 主题、语义色、字阶与 4/8 间距 token，不新增裸颜色或裸尺寸。每条建议使用 Mantine Button，最小触控高度 44px；宽屏按可用宽度排列，窄屏纵向排列并允许长文本换行。

控件选型：问题使用现有 Mantine Textarea；推荐项为只负责预填的 Mantine Button。点击后聚焦 Textarea，不发送请求。

长问题的按钮使用精简显示文案以控制移动端行高，同时通过可访问名称与悬停提示保留完整问题；点击始终填入完整问题。

## 推荐来源与确定性

- 读取 `GET /api/notes` 的首屏摘要，再最多读取两篇笔记详情；问题使用实际笔记标题与首个可用章节名。详情读取失败时可退化为真实来源文件名，不编造章节。
- 读取 `GET /api/wiki/entries`，最多读取一个社区详情；优先从“成员实体”小节提取实际实体名，明确以“知识图谱”提示用户询问实体之间的关联。
- 最多输出三条，按笔记后 wiki 的稳定顺序去重。无可用标题/章节/实体时不生成通用示例。
- 对 Skill 文件不做专门的宿主文件扫描；只要它已作为资料导入、由 API 返回为笔记，就和其他 Markdown 文档一样按标题/章节推荐。
- 在问答页每次重新显示且本地服务可用时刷新建议，因此从资料库完成导入后返回即可看到新内容。

所有数据只通过既有 localhost HTTP API 读取。推荐构造仅使用返回的展示标题、章节和实体名，不执行检索或回答校验，也不向模型发送额外请求。

## 空态与失败态

- 确认笔记与 wiki 均为空：显示简短导入提示，不显示固定样例。
- 推荐 API 暂时失败：不挡住输入；说明暂时无法读取推荐，用户仍可自行提问。
- 笔记或 wiki 任一侧可用：仅根据可用内容展示建议，不让另一侧失败清空已有建议。

## 方案自查

推荐内容来自当前本地语料的标题和结构，换一个用户或语料会得到不同问题；空语料不暴露“项目边界”等预设假设。问题仍由用户编辑和发送，核心问答操作与现有体验一致。
