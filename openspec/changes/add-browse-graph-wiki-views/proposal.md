# 提案：浏览/图谱/wiki 三个知识视图（围绕问答的只读补齐）

## Why

Phase 4 起前端只有问答闭环；浏览（vault 投影阅读）、图谱（实体关系画布）、wiki
（LLM 总目阅读）三个视图是 ui/README 与 ROADMAP 记录在案的遗留项，HANDOFF
（2026-09-19）列为下一阶段候选第 3 项。三者皆为只读消费：数据已全部由内核产出
（notes/ 投影、图谱 parquet、`data/wiki/entries/`），缺口是经 HTTP API 暴露读取面
并补三块界面。图谱可达 10⁵ 边级（ADR-0003 触发器量级），画布必须经内核做有界查询，
不能整库推送前端。

## What Changes

- 新增只读 API（additive，OpenAPI 快照显式刷新）：
  - 浏览：笔记投影的分页清单与单篇 Markdown 内容读取（含来源锚点元数据）。
  - 图谱：实体/边/社区聚合统计 + 有界子图查询（度数 top-N、实体搜索、邻域展开，
    服务端返回上限，超限裁剪并明示「已截断」）。
  - wiki：条目清单与单条内容读取（派生自 `data/wiki/entries/`，携带生成时间等
    时效元数据）。
- UI 新增三个视图与导航骨架：
  - 浏览视图：清单 + 单篇只读阅读（安全 Markdown 渲染、原件/锚点信息展示）。
  - 图谱视图：Sigma.js + graphology WebGL 画布（ui/README 既定路线）——节点搜索、
    邻域展开、社区着色、截断提示；实体可联动问答预填。
  - wiki 视图：条目列表 + 阅读 + 「可重建」时效提示。
- 全部视图只读：不提供编辑、生成、重建、删除入口。

## 受影响决策

- 红线 2 / ADR-0002：前端 SHALL NOT 读取 vault、SQLite、LanceDB、parquet——三个
  视图的全部数据经新增只读端点，ui/README 的既有承诺就此兑现。
- 红线 3 / ADR-0004：只读边界即语料保护——任何写回投影/图谱/wiki 的路径都不存在。
- ADR-0003：图谱存储三件套不变；读取面以服务端查询暴露。10⁵ 边换 igraph 的触发器
  不受影响（本 change 只加读取，不改抽取/存储）。

## 与项目路线的关系

HANDOFF 下一阶段候选第 3 项（排序在设置中心、资料管理之后）：属体验增强而非上手
阻断。浏览清单与资料管理 change 的来源清单同源，先行完成资料管理有价值，但无硬依赖。

## Non-goals

- 不做图谱/wiki 的生成与重建 UI（继续走 CLI；资料管理 change 亦不覆盖）。
- 不做笔记编辑与写回（红线 3：任何「顺手修改用户语料」的路径视为缺陷）。
- 不做独立全文搜索页（既有 `/api/search` 服务问答；独立搜索体验另行评估）。
- 不做跨 vault、分享、导出、打印排版。
- 不引入图数据库或图查询引擎（数据主权三件套不变）。
- 画布不做编辑器级功能（布局自定义、小地图、批量编辑）；除 Sigma.js/graphology 外
  不引入其他重前端依赖。

## 边界裁决

- 三个视图均为只读消费端：清单与内容一律经内核端点获取，前端不自行解析 parquet 或
  vault 文件。
- 图谱查询必须有服务端上限（返回节点/边数、展开深度），超限按度数/相关性裁剪并
  明示截断，防止大图拖垮传输与渲染。
- wiki/图谱内容标注数据时效（生成时间与来源身份）；过期派生物只提示「可重建」，
  不自动触发重建。
- Markdown 渲染 SHALL 产出只读安全输出（防注入），不执行任何内嵌脚本。
